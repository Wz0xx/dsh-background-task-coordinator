# 0.2.6 改动记录（2026-11-28）

**这一版是「对方按我的审查意见改完，我再把两边合起来」。**

上一轮（0.2.5）我把 Gemini 的 0.2.4 融合进来，并写了一份审查意见指出：
它的 `dataDir()` 丢了 `config.profile`（我这台机器必需）、它的 `resolveSubagentBinding`
有 fail-closed 误伤风险。

**它按这份意见改了，出了修订版。** 这一版采用它的修订版作为基础。

---

## 一、它改对了什么

### 1. `config.profile` 回到第一优先级

它重写成了 `resolveDataDir(configHint)`，返回 `{ dir, source }`：

```js
// ① config.profile / config.profileName（最高优先级，解决 host 子进程读不到 DSH_PROFILE* 环境变量）
// ② env.DSH_PROFILE_DIR（带非默认根目录 8 位指纹）
// ③ env.DSH_PROFILE / env.DSH_PROFILE_NAME
// ④ fallback(default)
```

**比我那版更好的一点**：`source` 由 `resolveDataDir` 自己返回，而不是在 `apply` 里
手工拼一个 `_profileHint ? 'config.profile' : ...`。少一处可能不一致的地方。

### 2. `resolveSubagentBinding` 的 fail-closed 边界写清楚了

我上一版指出的风险是「三处拿不到就拒绝，可能误伤」。它的修订版明确写了三条降级规则：

```
1. agents/sessions 暴露了父会话字段且不一致 → 一律拒绝
2. 宿主完全不提供 subagents 的三个方法 → 不误拒，交给元数据 + SQLite 唯一性兜底
3. 提供了枚举/解析服务 → 要求子树命中 或 resolveName 命中 或 元数据正向确权
```

第 3 条里的「元数据正向确权」解决了一个我没想到的场景：
**早到结束的子代理已经从 `listChildren` 移出**，但仍然应该允许绑定。

它专门加了 `21.5c` 测这一组边界：

```
noSub=true prunedSelf=true prunedOther=false
   无服务不误拒 ↑  ↑ 被裁剪的自己的子代理放行   ↑ 别人的仍拒绝
```

### 3. 补了 `config.profile` 的测试

`21.5a`（env 全空时 config 生效）、`21.5b`（config 优先于环境变量）。

## 二、我在它基础上改的两处

### 1. 修了 `21.5a` 的断言方式（它自己也挂在这条）

它的断言是用 `path.join(home, ...)` 猜路径：

```js
const deskDb = path.join(home, '.dsh', 'background-task-coordinator', 'desktop', 'tasks.db');
fs.existsSync(deskDb)     // ← 在 Windows 上 false
```

原因：`dataDir` 走的是 `os.homedir()`，而测试改的是 `USERPROFILE` / `HOME`
环境变量 —— 在当前 Node 版本上两者不同步。

改成**从日志里抠实际路径**：

```js
const deskPathMatch = deskLog.match(/台账目录：(.+?)（来源/);
const deskDb = deskPathMatch ? path.join(deskPathMatch[1], 'tasks.db') : null;
```

这样验的是插件真正用的那个目录，不是测试自己以为的。

### 2. `sanitize()` 没清洗空格 —— 这是它的真 bug

```js
// 它的
const sanitize = (s) => s.replace(/[\\/:*?"<>|\u0000-\u001f]/g, '_')...
```

空格能过。于是 profile 名是 `my profile` 时，会生成
`~/.dsh/background-task-coordinator/my profile/tasks.db` —— **目录名带空格**，
之后 shell、命令行工具、日志解析全都要额外处理引号。

我的测试 `23.4` 就是这么发现它的：

```
❌ 23.4 需清洗的名字加指纹  (a b_c-4947a3ad)     ← 空格还在
```

改成把 `\s` 也纳入替换集：

```js
const sanitize = (s) => s.replace(/[\\/:*?"<>|\s\u0000-\u001f]/g, '_')...
```

顺带的好处：名字被清洗过就走 fingerprint 分支，两个不同原名不会撞同一目录。

## 五、独立核实（不信它的测试，也不信我的）

写了一次性脚本单独验，不依赖任何测试文件：

```
=== 1. redactSecrets ===
  ✅ Bearer token 被脱敏
  ✅ env 赋值被脱敏
  ✅ URL 密码被脱敏
  ✅ 普通命令不受影响

=== 2. 落库脱敏 vs 投递原文 ===
  ✅ 库里 objective 已脱敏
  ✅ 投递给 agent 的是原文（未被脱敏）
  ✅ 库里消息已脱敏

=== 3. scrubbedParentEnv ===
  ✅ 过滤 API_KEY / TOKEN / PASSWORD / SECRET / DSH_*
  ✅ 保留 PATH / LANG
```

第 2 组仍然是最要紧的：脱敏只影响「存下来的那份」，
`ag.followup()` 收到的必须是完整指令 —— 否则子代理拿到的是没法执行的 `[REDACTED]`。

## 六、两版实现的取舍

为什么会走「先融合，再用对方的修订版」这条路，而不是一直只拿功能：

| | 我的 0.2.5 | 它的修订版 | 结果 |
|---|---|---|---|
| `config.profile` 第一优先级 | ✅ 有 | ✅ 有（更干净） | 用它 |
| `source` 来源标注 | 在 apply 里手工拼 | `resolveDataDir` 自己返回 | 用它 |
| 路径指纹防串库 | ✅ 有 | ✅ 有 | 用它 |
| `resolveSubagentBinding` 降级规则 | 只指出风险 | 写清了三条规则并测过 | 用它 |
| `sanitize` 清洗空格 | — | ❌ 漏了 | **我补** |
| v2→v3 迁移断言 | ✅ 有 | ❌ 没有 | **我补** |
| `resolveDataDir` 单测 | — | ❌ 没有 | **我补** |

**没有「哪一版更好」这个结论。** 它想得更全（安全加固、降级边界），
我这边补的是平台适配和测试覆盖。合起来才是完整的。

## 七、还剩什么

- **`working_directory: unsupported`** 仍未解决。已确认「服务在插件进程里取不到」，
  不是异常被吞。但 `task_create(type=job)` 实际能建成（走 `cwdFallback`），
  所以更像自检口径过严，而不是功能坏了。
- **`chmod` 只在 Unix 生效**，Windows 跳过 —— 这是对的，但意味着本机没有这层保护。

# 归档功能的真实边界（2026-11-27 实测）

## 结论先说

`workspaceController.archiveSession` **调用成功、数据真的写进去了**，但面板「子智能体」列表没变化。

## 证据链

1. **工具执行成功**：8 条任务落 `task.archived` 事件，时间戳连续（间隔约 10ms）
2. **台账标记成功**：8 条任务的 `labels.archivedSessionId` 都写了
3. **宿主存储写入成功**：`~/.dsh/storages/workspace.json` 的
   `global.archivedSessionIds` 从 53 条增到 59 条，包含我们传的 6 个裸 UUID
4. **面板没变**：截图显示 6 条仍挂在「6 个子智能体」下

## 发现的格式不一致

`~/.dsh/storages/workspace.json` 的 `global.archivedSessionIds` 里：

| 格式 | 数量 | 来源 |
|---|---|---|
| `session-<uuid>` | 44 | 宿主自己归档的（历史） |
| 裸 `<uuid>` | 9 | 本次插件写入的 + `bili-whale` |
| 其他 | - | `bili-whale` 这种自定义 id |

我们传的是裸 UUID，宿主接受并原样存了，**没做归一化**。

## 待验证

已手工往归档集补了 6 条 `session-<uuid>`，等面板刷新后确认：

- **如果消失** → 修法：`archiveSession` 前把 id 加 `session-` 前缀
- **如果还在** → 说明渲染 `subagentCatalog` 时根本不查归档集，
  这个 UI 层功能对本面板不生效，需要换路线（改父会话日志里的 catalog 事件，
  或者接受「归档只影响对话列表，不影响子智能体列表」）

## 关键代码位置

- 插件：`compat/session-archive.js` 的 `archiveSession()`
- 宿主接口：`ctx.get("workspaceController").archiveSession({sessionId, stopActivity?})`
  → `{archivedSessionIds: readonly SessionId[]}`
- 归档集持久化：`~/.dsh/storages/workspace.json` → `global.archivedSessionIds`
- 面板列表来源：父会话日志 `subagent/catalog` 事件（`{childId, childCreatedAt, mode, label}`），
  以及 `~/.dsh/storages/session_projcache/sessions/<session>.json` 的 `subagentCatalog` 投影

## 备份

改 `workspace.json` 前备份在 `workspace.json.bak-probe-<时间>`。
会话目录未受任何影响（归档只从列表移除，不删文件）。

# 本机测试方案与损坏修复手册（后台任务协调器）

适用：在本机直接落地测试后台任务协调器（阶段 0 → 阶段 1 验收）。
原则：**每一步动文件前先有备份；每个改动能一键回到测试前。**
制定日期：2026-11-24。适配 DSH 0.2.1-rc.4。

---

## 一、测试前快照（一次性，5 分钟）

测试只碰三处：DSH 安装目录（不碰）、`~/.dsh` 配置与会话、协调器自己的数据。
快照打前两处。

### 1. 完全退出 DSH（托盘也退，进程列表里没有 DSH NEXT 为止）

### 2. 打快照（PowerShell，整段复制执行）

```powershell
$stamp = Get-Date -Format 'yyyyMMdd-HHmm'
# ① 配置与插件组合（cordis.patch.yml 等）
 robocopy "C:\Users\stop\.dsh\profiles" "C:\Users\stop\.dsh\backup-pre-coordinator-$stamp\profiles" /E /NFL /NDL /NJH /NJS
# ② 会话目录的「文件名+大小+时间」清单（不复制几个 G 的会话本体，损坏时可比对）
 robocopy "C:\Users\stop\.dsh\sessions" "C:\Users\stop\.dsh\backup-pre-coordinator-$stamp\sessions-index" /L /E /NJH /NJS /FP | Out-File "C:\Users\stop\.dsh\backup-pre-coordinator-$stamp\sessions-listing.txt"
# ③ 已有会话级备份确认（昨晚已建过，确认还在）
 dir D:\DSH-session-backup | Out-File "C:\Users\stop\.dsh\backup-pre-coordinator-$stamp\d-drive-backup-check.txt"
echo "快照完成：C:\Users\stop\.dsh\backup-pre-coordinator-$stamp"
```

> 说明：会话本体不重复备份——`D:\DSH-session-backup\before-trim-20261124-010908`
> 已有家会话完整件；其余会话在测试期间 DSH 自己每轮都会写盘，
> 真损坏时按第四节「会话损坏」流程修，快照清单用于比对差异。

### 3. 记录基线：重启 DSH，正常用 10 分钟，确认一切如常。再开始装。

## 二、安装（阶段 0 实测）

每次改动只落两处：`cordis.patch.yml`（组合）和插件包目录。
**每改一次 cordis.patch.yml 前先复制一份带时间戳的副本**（脚本里已含）。

### 步骤

```powershell
# 1) 备份组合文件（每次改之前都跑）
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
Copy-Item "C:\Users\stop\.dsh\profiles\desktop\cordis.patch.yml" "C:\Users\stop\.dsh\profiles\desktop\cordis.patch.yml.bak-coord-$stamp"

# 2) 构建插件
cd C:\Users\stop\.dsh\worlds\default\room\background-task-coordinator
pnpm build

# 3) 组合文件末尾追加（先手动编辑，加完让 DSH 重载）
#   - name: dsh-background-task-coordinator
#     path: C:\Users\stop\.dsh\worlds\default\room\background-task-coordinator
```

### 验证点（每个点验证过在核验表打 ✅）

- [ ] V1 DSH 启动无报错，插件出现在插件面板
- [ ] V2 `cordis inspect` 能列出协调器的 provider/config
- [ ] V3 `ctx.jobs` 服务键名与预期一致（否则改 `JOBS_SERVICE_KEY`）
- [ ] V4 启动一条真后台 echo → 拿到 jobId → 输出回读成功
- [ ] V5 结算回调到达，任务标 completed，通知生成
- [ ] V6 Mode A 桩实测：插件层 agent handle 是否可达

### 阶段 0 的熔断线

V1 失败 = 插件骨架不兼容 → 停，回滚组合文件，不改任何核心代码继续查。
V3/V4 失败 = 只改 `dsh-plugin-adapter.ts` 绑定函数（预期内）。
V6 失败 = Mode A 永久搁置，Mode B 已够 MVP。

## 三、可逆性总则

| 改动 | 回滚方式 | 损失 |
|---|---|---|
| cordis.patch.yml 追加 | 还原 `.bak-coord-*` 副本，重启 DSH | 零 |
| 插件包更新 | `pnpm build` 重跑（无状态） | 零 |
| 协调器数据库 | 删 `~/.dsh/background-task-coordinator/tasks.db*` | 只丢任务台账 |
| 本机会话 | 见第四节 | 见第四节 |

**协调器的数据全部隔离在自己目录**（`~/.dsh/background-task-coordinator/`），
删掉它 = 完全卸载，不碰 DSH 任何原生数据。

## 四、坏了怎么修（按症状查）

### 症状 A：DSH 启动报错 / 插件加载失败

1. 还原组合文件：
   ```powershell
   Copy-Item "C:\Users\stop\.dsh\profiles\desktop\cordis.patch.yml.bak-coord-<最新>" "C:\Users\stop\.dsh\profiles\desktop\cordis.patch.yml" -Force
   ```
2. 完全退出 DSH 再启动。
3. 仍报错 → 组合文件里逐行注释掉协调器相关条目再试。
4. 仍不行 → 用快照：把 `backup-pre-coordinator-*\profiles` 整个复制回
   `C:\Users\stop\.dsh\profiles\`（覆盖前先复制当前版做 `profiles.broken`）。

### 症状 B：协调器导致宿主卡死 / 内存暴涨

1. 任务管理器结束 DSH NEXT 全部进程。
2. 还原组合文件（同症状 A 第 1 步）——先禁用插件再谈别的。
3. 删除协调器数据目录（诊断信息在里面，删前可拷一份到桌面）。
4. 重启 DSH，确认恢复基线，再分析桌面上的诊断副本。

### 症状 C：会话文件损坏（昨晚那种 corrupt / seq gap）

**先别删任何东西。** 昨晚的修复链全部可复用：

1. 单帧 zstd → 多帧：`room\tools\重排多帧.mjs`（Node 版，先对比帧描述符）。
2. 帧描述符必须是宿主的 0x04：`room\tools\重排宿主帧.py`。
3. 物理删行导致的 seq 断号：**不可修**，只能回完整备份——
   `D:\DSH-session-backup\` 或会话目录内 `.bak-*`。
4. 全部失效时：`sessions-listing.txt`（第一节快照）比对哪个文件异常，
   把坏件移到草稿区（不删），用 D 盘备份还原，重启 DSH。
5. 恢复后用「从头翻老记录」验证内容完整，确认前不清理任何备份。

### 症状 D：QQ 消息异常（qq-native 链路被测试扰动）

1. 先查是 dsh-world 插件自身状态问题还是协调器引入——
   禁用协调器（组合文件注释掉）后 QQ 恢复即协调器问题。
2. dsh-world 自身：QQ 状态端点
   `/dsh-world/worlds/default/qq/native`（GET 带 `sec-fetch-site: same-origin`），
   rejected/dropped 计数在面板可查。
3. 组合层面 dsh-world 的 patch 副本在 `cordis.patch.yml.bak-*` 系列里。

### 症状 E：测试把任务台账写乱（状态不一致 / 重复任务）

- 台账只是投影：删 `tasks.db*` 三件 → 重启 DSH → 协调器重建空库。
- 原生执行单元状态永远以 DSH 为准，台账坏了不影响原生。

## 五、测试节奏

1. 每完成一个验证点（V1–V6），核验表更新一行结论。
2. 破坏性用例（测试 E/F）放在当天最后一轮，测完立即回滚验证一次。
3. 30 分钟稳定性（阶段 4）由协调器自己跑自己的任务，人不用盯。
4. 全部通过后：保留 `backup-pre-coordinator-*` 快照 30 天再清理。

# 0.1.9 改动记录（2026-11-27）

对应《cwd 缺陷报告》（0.1.6 / 0.1.7 在 DSH 0.2.2-rc.5 上建 job 恒失败）。

---

## 核心缺陷：用直取方式访问未 inject 的服务

### 报告说的

`ctx.workingDirectory` / `ctx.sandboxPolicy` / `ctx.sandbox` 三个服务不在 `inject` 列表里。
cordis 4.x 对「未注入就取」是**抛错**而不是返回 `undefined`：

```
cannot get property "workingDirectory" without inject
```

抛在**取属性**这一步，`?.` 救不了。外层 `catch {}` 把错吞掉，`cwd` 恒为 null，
于是 job 一律被拒。

### 我核实了什么

1. **cordis 的 Proxy 语义**（`app.asar` 里 `ReflectService.handler.get`）：
   属性不在白名单里就 `new Error(...)`，然后走 accessor 或 waterfall 抛出。
   **确认是抛错，不是 undefined。**
2. **不能靠加 `inject` 修**：报告 §3.4 实测——加了 `workingDirectory` 后
   整个插件不启动，8 个工具全变 `unknown tool`。
3. **本机 11-24 就踩过同一个坑**：那时 `ctx.jobs` 报 `cannot get property "jobs" without inject`，
   我是往 `inject` 里加 `'jobs'` 修的。**然后写新代码时又用了直取**——同一个教训还回去了。

### 改了什么

**`index.js` 的 cwd 段**：

```js
// 旧
if (ag) cwd = await ctx.workingDirectory?.ensure?.(ag, undefined) ?? null;

// 新：可选服务查询
const svc = (name) => {
  try { return typeof ctx.get === 'function' ? ctx.get(name) : undefined; }
  catch { return undefined; }
};
const wd = svc('workingDirectory');
if (ag && wd && typeof wd.ensure === 'function') cwd = await wd.ensure(ag, undefined) ?? null;
```

**sandbox 段**：同样改成 `svc('sandboxPolicy')` / `svc('sandbox')`。

**自检三项**（否则会一直误报 `unsupported`——那是同一个 bug 的另一面）：

```js
'working_directory': { status: has(() => typeof ctx.get?.('workingDirectory')?.ensure === 'function'), required: true },
'sandbox.confine':   { status: has(() => typeof ctx.get?.('sandbox')?.confine === 'function'), required: false },
'sandbox.policy':    { status: has(() => typeof ctx.get?.('sandboxPolicy')?.resolve === 'function'), required: false },
```

`working_directory` 同时从 `required: false` 改成 `required: true` —— job 没有它必败。

**`compat/subagents-adapter.js`**：`getSubagentsService` 删掉「退回直取」那句
（直取会抛，虽然被 catch 兜住，但那是死路，留着让人误以为有第二条路）。

**诊断文案**（报告 §4.4）：cwd 取不到时把**原因**写出来，不再只说「拿不到」：

```
建任务失败：拿不到本会话的工作目录（cwd）——原因：<真实异常>。（taskId=xxx）
```

## 顺带修的两条（深度审计遗留）

### P2-9 通知措辞撒谎 —— 已改

`settleNotification` 只写幂等账 + 事件流水，**不投递任何消息**。
job/subagent 正常结束靠 DSH 原生通道回前台；但 `lost` 这类协调器自产的终态
没有任何原生事件，前台实际收不到东西。

旧事件文案写「通知已入账（原生通道送达）」—— **那是假的**。改成：

```
终态 lost 已记账（仅台账；本插件不主动投递消息）
```

### P2-2 `stopReason` 误判为成功 —— 已改白名单

旧逻辑：只认 `cancel`/`fail`/`error`/`abort`，**其余一律 `succeeded`**。
`max_turns`、`timeout`、`interrupted`、`budget_exceeded`、空字符串全都会落成「成功」。

新逻辑：白名单 `completed|end_turn|stop|stop_sequence|success|succeeded|done` 才算成功，
其余一律 `failed`，并把原始 `stopReason` 写进 `errorSummary`（`end: max_turns`），
让人看得出到底怎么停的。

## 测试体系：从 /tmp 搬进仓库

之前所有回归都散在 `/tmp/coord-*.mjs`，仓库里零可执行测试（审计报告 §1 也点了这条）。

现在：

- `tests/mockctx.mjs`：统一的 Cordis ctx mock，**行为对齐真实宿主**——
  核心方法（`on`/`tools`/`logger`）可直取，未 inject 的服务直取抛 `without inject`，
  `ctx.get(name)` 是可选查询、永不抛
- `tests/regression.mjs`：16 项，覆盖建 job / confine / describe / 幂等 /
  越权拒绝 / 自己取消 / subagent 结算 / stopReason 白名单 / `ag.cancel` /
  长 objective / 自检三项 / 通知事件
- `package.json` 加 `"scripts": { "test": "node tests/regression.mjs" }`
- 删掉 `tests/*.test.ts` 与 `helpers/`（它们 import 已删除的 `lib/core`，跑不起来）

**这个 mock 本身就是本轮的关键教训的固化**：
以后谁再写 `ctx.xxx` 直取未注入的服务，测试会立刻抛 `without inject`。

### 守住的（它的改动会破坏，必须保留）

**`dataDir(configHint)` 的 `config.profile` 支持。**

Gemini 版改成只认环境变量：

```js
function dataDir() {                      // ← 没有 configHint
  const raw = process.env.DSH_PROFILE_DIR;
  ...
}
```

他那边（Linux）环境变量能传进插件进程，所以够用。**但这台机器传不进来** ——
今晚实测的证据：日志一直是 `来源：fallback(default)`，台账落在 `default/`，
和真数据（`desktop/` 里 29 条任务）分家。

融合后的来源顺序：

```
① config.profile（本机必需）
② env.DSH_PROFILE_DIR（他的环境够用）
③ env.DSH_PROFILE / DSH_PROFILE_NAME
④ default
```

而且 **config 来的名字也参与他那个路径指纹计算** —— 两边优点都留：
纯名字不加指纹（向后兼容），非标准路径加 `<name>-<hash8>`（不串库）。

实测输出：

```
22.1 config.profile 生效（env 为空时）       → desktop
22.4 config 给的纯名字不加指纹（向后兼容）    → default
22.5 config 给非标准路径时加指纹（不串库）    → default-a9197a06
22.6 config 压过 env                        → fromconfig
22.7 无 config 时 env 兜底                  → fromenv
```

## 二、修了它 2 项挂掉的测试（是平台差异，不是功能问题）

Gemini 那边 121 项挂 2 项：

```
❌ 21.1a 子进程过滤宿主凭据与 DSH_*（danger-full-access）
   ('C:\Program' 不是内部或外部命令)
❌ 21.1b 子进程过滤宿主凭据与 DSH_*（workspace-write）
```

**原因不是代码，是测试构造。** 它这样写：

```js
const cmd = `"${process.execPath}" -e "${probeScript.replace(/"/g,'\\"')}"`;
```

- **Linux**：`bash -c` 会正确剥引号 → 通过
- **Windows**：走 `cmd /d /s /c` + `windowsVerbatimArguments`，引号变字面量 → 报错

而且这台机器的 `process.execPath` 是 `C:\Program Files\DSH NEXT\...\node.exe`：
**不加引号被空格劈开，加了引号变字面量** —— 两头堵。

最终解法：Windows 上改用 PATH 里的 `node`（无空格）+ 临时脚本文件。

```js
if (process.platform === 'win32') {
  const scriptFile = path.join(tmpdir, 'probe.cjs');
  fs.writeFileSync(scriptFile, probeScript);
  cmd = `node ${scriptFile}`;          // 两段都不含空格
} else {
  cmd = `"${process.execPath}" -e "${probeScript}"`;   // Linux 原样
}
```

修完这两条真的在验功能了（输出证明）：

```
{"k":null,"t":null,"p":null,"d":null,"s":"safe-keep-val","sb":"from-sandbox"}
   ↑ 四个凭据全被过滤      ↑ 正常变量保留   ↑ 沙箱注入正常透传
```

## 五、独立核实（不信它自己写的测试）

写了个一次性脚本单独验，结果：

```
=== 1. redactSecrets ===
  ✅ Bearer token 被脱敏     "curl -H \"Authorization: [REDACTED]\""
  ✅ env 赋值被脱敏          "DEEPSEEK_API_KEY=[REDACTED]"
  ✅ URL 密码被脱敏          "psql postgres://u:[REDACTED]@h/db"
  ✅ 普通命令不受影响         "npm run build"

=== 2. 落库脱敏 vs 投递原文 ===
  ✅ 库里 objective 已脱敏
  ✅ 投递给 agent 的是原文（未被脱敏）
  ✅ 库里消息已脱敏

=== 3. scrubbedParentEnv ===
  ✅ 过滤 API_KEY / TOKEN / PASSWORD / SECRET / DSH_*
  ✅ 保留 PATH / LANG

=== 4. 权限 ===
  平台 win32 → 跳过 chmod（符合预期）
```

**第 2 组最要紧**：它证明脱敏只影响「存下来的那份」，
`ag.followup()` 收到的仍是完整指令 —— 如果这层没分开，子代理会收到 `[REDACTED]` 而没法干活。

## 六、还剩什么

- **`working_directory: unsupported`** 仍未解决。已确认是「服务在插件进程里取不到」，
  不是报错被吞（`capErrors` 为空）。根因和 `DSH_PROFILE_DIR` 一样。但 `task_create(type=job)`
  实际能建成（走 `cwdFallback`），所以更像自检口径过严。
- **`resolveSubagentBinding` 的 fail-closed 边界**：它有好几处「拿不到就拒绝」。
  本机 `listChildren` 可用所以能过，但如果宿主某版本三个方法都没有，正常绑定会被误伤。
  这一点它的实现里有一条「全都没有 → 依赖 metadata 与台账唯一性」的兜底，但没测过那条路。

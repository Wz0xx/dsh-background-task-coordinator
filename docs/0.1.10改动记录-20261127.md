## 补丁 2：`exec.agent` 空就拒建 —— 已采纳，四级兜底

**改前**：只用 `exec?.agent`，取不到就直接 `failed: working directory unavailable`。

**问题**：0.2.2-rc.3 上 `exec.agent` **经常为空**（同一条会话里时有时无）。于是同一句
「帮我跑个构建」有时能建、有时拒建 —— 对使用者就是**随机失败**。

**改后**（四级）：

1. `exec.agent`
2. 台账 `ownerSessionId` → `ctx.get('agents').get(...)`
3. 会话头的 `sessions.get(owner).header.cwd`（服务可能存在也可能不存在）
4. **退回 `process.cwd()`，但打 `cwdFallback: 'true'` 标记**

落账时把 `cwd` 和 `cwdFallback` 都写进 `labels`，事后能分辨「这条任务跑在哪儿」。

设计取舍：宁可跑在进程目录并标注，也不要随机拒建（反馈原话）。

## 补丁 3：`sandboxPolicy` 取不到被误判「沙箱拒绝」 —— 已采纳，还多修了一层

**反馈说的**：`inject` 里没有 `sandboxPolicy`，取值抛 `without inject`，
外层 catch 一律当成「会话不允许自由 shell」。

**改后**：catch 里区分两类：

```js
const unavailable = /without inject|not registered|unknown service|is not a function/i.test(msg);
const label = unavailable ? 'sandbox 服务不可用' : 'sandbox 拒绝';
const hint = unavailable
  ? '插件侧拿不到 sandbox 服务（不是你的会话有问题）'
  : '当前会话沙箱策略不允许自由 shell';
```

### 但我顺着查下去，发现自己修错了一层

读宿主的 `SandboxPolicyService` 定义，`resolve(request = {})` 的 `session` 是**可选**的，
原文注释写着：

> A session cwd is its workspace-write boundary; the configured root is the fallback for
> **agentless calls** and sessions without a cwd.

也就是说：**没有 agent/session 也能 resolve**，宿主会退回部署默认模式。

我在 0.1.9 里写的是 `ag ? resolve({session}) : null` → 拿不到 agent 就直接拒建。
那等于把「宿主明明支持无 session 调用」硬做成 random failure。

**改后**：`await sbp.resolve(ag ? { session: ag.session } : {})` —— 拿不到 agent 就传空对象，
让宿主用自己的默认策略。fail-closed 还在（真有服务不可用/无返回就拒），
但不再因为「这次没拿到 agent」而拒。

这一条是我自己查出来的，反馈里没提。

## 补丁 4：`task_cancel` 可能永等终态 —— 已采纳，且这坑是我 0.1.9 埋的

**反馈点名的坑**：

> 如果直接写 `ctx.agents.get(row.nativeSessionId || row.nativeId)`，
> null 时会拿 **agent 名字**去按 session id 索引的注册表里查 → 恒空 →
> 把**还活着的** subagent 判成已回收，直接落 `cancelled`。

**我 0.1.9 的代码正是这么写的**：

```js
const ag = getAgentHandle(ctx, t);   // 内部 nativeSessionId || nativeId
...
} else {  // ag 为 undefined
  /* 落 cancelled —— 误杀 */
}
```

**改后**：

```js
const hasRealId = !!t.nativeSessionId;
const ag = hasRealId ? getAgentHandle(ctx, t) : undefined;
if (ag && ag.cancel) { ag.cancel(...); nativeOk = 'agent.cancel(keepInbox)'; }
else if (ag) { nativeOk = 'agent 无 cancel 方法，等 subagent/end 确认'; }
else if (!hasRealId) {
  // 没有真 id：探不了，不能断定死活。记 cancel_requested，交给重启对账/超时清账收尾
  nativeOk = '未解析出会话 id，未探活（无法确认原生状态）';
} else {
  /* 真 id 且查不到 → 才落 cancelled */
}
```

## 补丁 1：限额默认 3/2 → 5/4

采纳建议的中间档。重度用户（4~6 条并存）可以用 `DSH_COORD_LIMITS` 调更大，
但默认不该逼着所有人一开始就改配置。

## 顺带两条

### `getAgentHandle` 不再把异常吞成 `undefined`

原来内部 `try { ... } catch { return undefined; }`，导致调用方分不清
「查不到（agent 真没了）」和「查询本身失败」。现在只让「服务取不到」退化为 undefined，
`get()` 抛错就让它冒出去，调用方据此判断「这次探活没做成」。

### `sweepOnce` 的 docblock 过时

原来写「`task_list` 与 `task_describe` 都调」，0.1.7 修 A1 之后只剩 `task_list`。
照旧注释重打补丁会把副作用引回来。已改成明确写「只有 `task_list` 调」。

---

## 关于「保留 inject 直取」的取舍

反馈建议「把 `sessions` / `sandboxPolicy` 加进 `inject`」。

**没采纳**，理由是同日的 cwd 缺陷报告 §3.4 实测过：**加了注入会让整个插件不启动**，
8 个工具全变 `unknown tool`。所以本插件一律走 `ctx.get()` 查询式取服务，
不加 inject。这是两份反馈冲突的地方，我按实测的那份办。
